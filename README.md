# Андрей Петров — «Логика и практика»

Персональный профессиональный лендинг Андрея Петрова, объединяющий направления работы, реальные проекты и цифровые продукты в единую визуальную систему. Через проекты сайт показывает подход: разобраться в задаче и исходной ситуации → увидеть связи и контекст → выстроить логику решения → превратить её в концепцию, проект, цифровой продукт или работающий инструмент.

Это профессиональный лендинг, а не классическое портфолио дизайнера или резюме. Планируемая структура: Hero → 10 последовательно расположенных проектных блоков → финальные смысловые разделы. Состав будущих финальных разделов уточняется перед их реализацией.

## Локальный просмотр

Откройте `index.html` двойным кликом в современном браузере с включённым JavaScript. Сайт работает через `file://`; локальный сервер, Node.js и установка зависимостей для просмотра не требуются.

Папки `src`, `REFERENCES`, «Вайфреймы в работу» и `index.html` должны сохранять установленную структуру и взаимное расположение. Пути и имена исходных файлов, включая кириллицу и пробелы, необходимо сохранять.

Просмотр через HTTP также поддерживается. Например, из корня проекта при установленном Python:

```powershell
python -m http.server 8000
```

Адрес просмотра: `http://localhost:8000/`. Сервер является дополнительным способом просмотра, а не обязательным условием работы.

## Архитектура и структура

Проект строится модульно. Каждый крупный проект имеет собственную структуру, стили и данные, а его изображения находятся в соответствующей папке `REFERENCES`. Изменения внутри одного проекта должны оставаться локальными; изменения общих компонентов требуют проверки всех использующих их блоков.

Повторяющиеся механизмы — навигация, CTA, галерея и lightbox — реализованы как переиспользуемые модули. Текущая реализация использует обычные HTML, CSS и JavaScript без фреймворка и сторонних runtime-зависимостей.

```text
index.html                     Точка входа, подключает base.css и site.js
```

JavaScript-исходники используют ES-модули. `index.html` подключает готовый `src/site.js` как обычный скрипт с `defer`: это обеспечивает открытие через `file://` без загрузки модулей браузером.

После изменения JavaScript-модулей разработчик обязательно обновляет готовый скрипт из корня проекта:

```powershell
node tools/build.mjs
node --check src/site.js
```

`src/site.js` не редактируется вручную. После изменений только CSS сборка JavaScript не нужна. Для обычного просмотра сборка не требуется.

Текущий сборщик поддерживает используемые в проекте именованные относительные импорты и объявления экспортируемых `function`, `const`, `let`, `class`. Это специализированный сборщик, а не поддержка произвольного синтаксиса ES-модулей: новый синтаксис импортов или экспортов необходимо сначала проверить на совместимость.

Новые проекты подключаются в `src/main.js`: в упорядоченный массив `projects` добавляется запись с номером, названием, ID реально существующего контейнера и функцией `render`. Этот же массив передаётся в `appendProjects` для сборки страницы и `mountProjectNavigation` для регистрации переходов. `appendProjects` автоматически вставляет общий разделитель перед каждым проектом, кроме первого. Стили проекта подключаются через существующую цепочку CSS-импортов. Галереи помечаются `data-gallery` и подключаются через `mountGallery`; данные превью должны соответствовать контракту этого модуля.

## Визуальные принципы

Сайт строится как длинный журнальный / editorial-лендинг с единым профессиональным визуальным языком:

- крупная журнальная типографика и выразительная работа с масштабом;
- чередование светлых и тёмных пространств;
- большие изображения и интерфейсы;
- сочетание полноширинных и структурированных секций;
- контролируемое свободное пространство и строгая сетка;
- визуальный ритм между проектами;
- минимум декоративных элементов, не несущих функции.

АРК задаёт уровень качества и общий визуальный язык, но не служит шаблоном для буквального копирования. Проекты 02–10 должны иметь собственную композицию и характер подачи в рамках общей системы. Нельзя повторять структуру АРК десять раз с заменой текста и изображений.

Уже принятые композицию, типографику, тексты, фоны, изображения и функциональность сохраняют, если конкретное задание не требует их изменения.

## Системный разделитель проектов

Подготовленный разделитель используется **между всеми последовательными проектами портфолио 01–10**: 01 → 02, 02 → 03 и далее до 09 → 10 по мере добавления проектов. Это постоянный общий элемент лендинга, который не принадлежит отдельному проекту.

Используется исходный `Вайфреймы в работу/Разделитель.svg`, корректно отображающийся через `file://`. Его пропорции и визуальный характер сохраняются: изображение масштабируется на полную ширину, высота определяется автоматически, кадрирование и деформация не применяются. Исходный SVG имеет размер 5506 × 70.

Стандарт перехода между всеми проектами: **конец проекта → белое пространство → разделительная полоса → белое пространство → начало следующего проекта**. Над и под SVG предусмотрены одинаковые белые вертикальные отступы, каждый равен высоте отображаемой полосы. Они адаптируются к ширине страницы по исходным пропорциям SVG `5506 × 70`; общая высота переходной зоны составляет три высоты полосы. Сам SVG и его внешний вид не изменяются.

Белый фон и отступы принадлежат общему компоненту `.project-separator` в `src/styles/project-separator.css`, а не Hero или footer проектов. Разделитель автоматически добавляется функцией `appendProjects` из `src/shared/project-separator.js`; вручную дублировать его внутри проектных секций не нужно. Перед первым проектом, между Hero и АРК, внутри проектов и после последнего проекта разделитель не вставляется.

## Адаптивность

Desktop-композиция должна сохранять целостность при различных размерах и соотношениях сторон окна. Минимально обязательные контрольные ширины: **1920, 1440 и 1280 px**. После существенных изменений проверяется вся страница, а не только изменённая секция, в том числе через `file://`.

Недопустимы случайные белые полосы и разрывы между секциями, искусственные пустоты из-за неверных размеров, столкновение текста со значимой визуальной частью, выход текста за контейнер, горизонтальный скролл, деформация изображений и уменьшение основной области сайта служебными элементами.

Осознанное кадрирование фонов и превью, размещение текста поверх предусмотренного для него фона, а также раскрытие overlay-навигации поверх страницы допускаются. Запрет на обрезание относится к непредусмотренной потере значимого контента, а не к утверждённому композиционному кадрированию.

Секции адаптируются к viewport, а не к диагонали монитора. Контентные блоки должны вмещать текст; ограниченная высота допустима для согласованных визуальных сцен с кадрированием. Применение `height`, `min-height`, `100vh`, `background-size` само по себе не является ошибкой — проверяется результат их работы.

Hero выполнен по новому центрированному референсу: имя, двухстрочный заголовок, пять направлений, горизонтальная лента и нижний текст. Пропорции масштабируются вместе по ширине и доступной высоте desktop-окна. Системный горизонтальный scrollbar скрыт; неподвижные градиенты цвета фона мягко растворяют края ленты. Десять карточек идут в порядке 01–10; лента бесконечно повторяет цикл в обе стороны, бесшовно проходя границу 10↔01. Визуальные повторы сохраняют клики и синхронный hover; доступная для клавиатуры и скринридера основная последовательность не дублируется. Номера нанесены средствами CSS поверх исходных изображений: тёмный полупрозрачный слой с тонким светлым контуром для читаемости на тёмных участках. Hover поднимает карточку ровно на 5 px без масштабирования и теней. Прокрутка доступна колёсиком, горизонтальным жестом, перетаскиванием и стрелками клавиатуры; карточки 01–10 плавно переводят к началу соответствующих проектов существующей механикой навигации.

Hero и АРК соединены без разделителя и дополнительного зазора. При вертикальной прокрутке Hero остаётся позади (`position: sticky`) и спокойно уменьшается максимум на 8% и затемняется максимум на 18% синхронно прогрессу прокрутки; при обратном скролле оба эффекта возвращаются к исходному состоянию. АРК поднимается поверх него. После полного перекрытия содержимое Hero скрывается, а проекты продолжают обычную прокрутку. Эффект изолирован в модуле Hero; внутренние стили проектов и правая навигация сохранены. При `prefers-reduced-motion` уменьшение и плавные анимации отключены. Reload продолжает использовать мгновенное стандартное восстановление позиции браузером.

Отдельная планшетная и мобильная адаптация нового Hero на этом этапе не выполняется. Перестроения секций всех четырёх проектов для узких экранов сохранены. В SVETLO и проекте 04 на узком экране тексты Hero и результата располагаются отдельно от изображений, текстовые столбцы становятся последовательными, галерея перестраивается в две колонки. Наличие этих правил не заменяет отдельную проверку мобильной версии. Новый Hero обязательно проверяется на 1920, 1440 и 1280 px; набор проверок проектов дополнительно охватывает 1024 px.

## Навигация проектов

Правая панель 01–10 — фиксированный overlay у правого края, центрированный по высоте окна. Она не участвует в layout основного контента, не создаёт отдельную колонку и не сдвигает секции.

Текущие размеры: 50 px в свёрнутом состоянии и 236 px в раскрытом; высота каждой строки — 36 px, между строками есть разделители. В обоих состояниях одинаковы высота панели, размеры строк, типографика и положение номеров. Номера остаются у правого края, а названия появляются слева. Правая граница неподвижна; меняется только ширина панели. Скруглены левые верхний и нижний углы. При малой высоте окна панель ограничена 90dvh и допускает внутреннюю вертикальную прокрутку.

Раскрытие работает при наведении и фокусе внутри панели. Взаимодействие указателем фокусирует её; клик снаружи снимает фокус, Escape также снимает фокус. Пока указатель находится над панелью, наведение продолжает удерживать раскрытое состояние.

Названия пунктов: АРК, Грантмастер, SVETLO, Индустриальная история, Агент.Метрика, Студия рассылок, Реестр ЗАЛов, 8 филиалов, Рабочий компас, Мобильные приложения.

Перед проектами расположена служебная ссылка «Главная», после проекта 10 — неактивная ячейка «Обсудить» без перехода. Обе ячейки занимают всю ширину панели, не имеют номера и вертикального разделителя, текст центрирован. «Главная» плавно возвращает к началу документа с учётом sticky-позиционирования Hero. Размеры и активное состояние нумерованных строк сохранены; после перехода и ухода указателя меню автоматически сворачивается.

Переходы подключаются только к зарегистрированным реализованным проектам. Активный проект выделяется через `aria-current` и рассчитывается по фактическим границам контейнеров при прокрутке, изменении окна и размеров проектов. Обновления объединяются через `requestAnimationFrame`; линия определения проекта находится на 15% высоты окна, максимум 160 px от верха. Это работает и при плавном скролле, и при прямом переходе в середину большого проекта. На всех секциях АРК активен 01, на всех секциях «Грантмастера» — 02, на всех секциях SVETLO — 03, на всех секциях индустриального музея — 04, Агент.Метрики — 05, Студии рассылок — 06, Реестра ЗАЛов — 07, сервиса «8 филиалов» — 08, «Рабочего компаса» — 09, «Мобильных приложений» — 10. Пункты ведут к контейнерам `project-01`–`project-10`; все десять пунктов доступны. Размеры и overlay-механика панели сохранены.

## Галереи и lightbox

Все три превью АРК являются интерактивными элементами одной галереи. Под ними остаются только названия изображений. Нумерация вида `01 / 03` и оранжевый значок около «3 скриншота» удалены. Клик по любому превью открывает именно его исходный файл в полноэкранном модальном lightbox. Верхние стрелки в блоке превью открывают последнее или первое изображение; переключение внутри открытого lightbox выполняют его собственные кнопки.

Общий `mountGallery` добавляет индикатор увеличения только на первую миниатюру каждой галереи проектов 01–09. Используется исходный `Вайфреймы в работу/Лупа.svg`: полупрозрачная белая лупа на мягкой тёмной круглой подложке в нижнем правом углу превью. Стили переиспользуются из `src/styles/shared.css`; индикатор декоративный, клик обрабатывает существующая кнопка превью. Остальные миниатюры, сам lightbox и проект 10 не меняются.

В левом верхнем углу lightbox отображается только название текущего изображения. **Счётчика изображений нет.** Кнопки листания оформлены симметричными оранжевыми кругами с белыми стрелками.

Поддерживаются:

- циклическое листание кнопками и клавишами ← / →;
- закрытие кнопкой и Escape;
- увеличение и уменьшение кнопками + / −, клавишами + / − и колёсиком мыши;
- двойной клик: увеличение до 300% или сброс уже увеличенного изображения;
- сброс масштаба кнопкой с процентом или клавишей 0;
- перетаскивание увеличенного изображения с ограничением смещения;
- пересчёт вписывания при изменении размера окна;
- блокировка прокрутки страницы на время просмотра и возврат фокуса к элементу, открывшему lightbox.

100% означает исходный режим вписывания изображения в доступную область без увеличения сверх его натурального размера, а не обязательный показ пиксель в пиксель. Максимальный относительный масштаб — 1200%. При смене изображения масштаб и смещение сбрасываются.

Общий модуль используется в следующих проектах там, где нужен просмотр интерфейсов или других материалов.

В «Грантмастере» галерея содержит три назначенных исходника с актуальными именами: `1 Главная и диагностика.png`, `2 Карта логики проекта.png`, `3 Конструктор проекта.png` из `REFERENCES/02_Грантмастер`. `2 — копия.png`, `mockup 1.png` и другие файлы для неё не используются. Все три превью открывают исходники одной галереи с тем же переиспользуемым lightbox и управлением, что и АРК; галереи проектов листаются независимо.

В SVETLO галерея содержит строго `2.png`, `3.png`, `4.png`, `5.png` из `REFERENCES/03_Светло`. Эти же файлы используются для превью и полноразмерного просмотра. Длинные скриншоты кадрируются снизу только в превью; в lightbox загружается полный исходник. Просмотр подключается существующим `mountGallery`, который использует общий `createLightbox`; отдельный механизм для проекта 03 не создаётся. Названия в lightbox соответствуют текущему изображению; галерея листается независимо от материалов АРК и «Грантмастера».

## Общий стандарт секций интерфейса и прокрутки

Все галереи проектов 01–04 имеют общую рубрику «ИНТЕРФЕЙС И РАЗДЕЛЫ». Общие стили вынесены в `src/styles/interface-section.css`: оранжевый цвет, размер рубрики в 1.5 раза больше обычной `.eyebrow`, прежние начертание и letter-spacing. Сразу под рубрикой находится существующий описательный текст проекта. Крупные заголовки, счётчики, чипы и другая служебная информация под описанием удалены. Подписи превью остаются без нумерации, имеют единые размер, цвет, отступ и выравнивание слева. Состав изображений и общий lightbox сохранены.

Корневой `scroll-behavior` — `auto`: браузер мгновенно восстанавливает собственную позицию после reload и при переходах по истории. Глобальное `smooth` здесь применять нельзя: оно вызывает видимое пролистывание при восстановлении. Клики по боковой навигации отдельно выполняют `scrollIntoView({behavior:'smooth'})`, сохраняя hash и историю через `history.pushState`. При `prefers-reduced-motion: reduce` переход мгновенный. Приложение не заменяет стандартное восстановление позиции своей системой хранения scroll offset. Исходные атрибуты `width` и `height` разделителя и крупной сцены SVETLO резервируют высоту до загрузки изображений, не меняя их видимую композицию и масштабирование.

Для проверки мгновенного reload без показа верха страницы и сохранения плавных кликов:

```powershell
node tools/verify-scroll.mjs
```

Тест использует тот же Chrome на порту 9222, проверяет проекты 03 и 04 с hash и без него на ширинах 1920, 1440 и 1280 px, измеряет положение при первых отрисовках и в последующих кадрах.

## Ссылки и CTA

Проект 04 не опубликован: внешние ссылки и CTA отсутствуют во всех его секциях. Галерея содержит строго `3.png`, `4.png`, `5.png`, `6.png` в указанном порядке. Она подключается существующим `mountGallery` и общим `createLightbox`, сохраняя листание, zoom, drag, клавиатуру, закрытие и восстановление фокуса.

SVETLO не имеет опубликованного сайта. В его Hero и результате нет CTA «Перейти на сайт» и нет временных, фиктивных или заглушечных ссылок. Правая часть финальной сцены остаётся свободной для изображения.

Основное действие оформляется одной понятной CTA в соответствующей секции. В АРК кнопки «Перейти на сайт →» ведут на `https://ark-culture.ru/`, открываются в новой вкладке и имеют `rel="noopener noreferrer"`.

В первом и финальном блоках «Грантмастера» CTA «Перейти на сайт →» ведут на утверждённый адрес `https://грант-мастер.рф/` с теми же правилами открытия. Ссылка хранится в `src/projects/grantmaster/data.js`.

В секции «Результат» оставлена только CTA; отдельная текстовая ссылка `ark-culture.ru` удалена. Не следует дублировать рядом одну и ту же ссылку кнопкой и текстом без специального указания в дизайне. Наличие CTA в разных смысловых секциях допустимо.

## Проверка реализации

`tools/verify.mjs` использует Chrome DevTools Protocol без сторонних пакетов. Для запуска нужен Node.js с глобальными `fetch` и `WebSocket` (текущий рабочий вариант — Node.js 24) и запущенный Chrome с портом отладки 9222 и открытой вкладкой. Для отладки следует использовать отдельный профиль, например внутри `.preview`, и ограничивать доступ локальным компьютером.

Из корня проекта:

```powershell
node tools/verify.mjs --file
node tools/verify-hero.mjs --file
node tools/verify-newsletter.mjs --file
node tools/verify-registry.mjs --file
node tools/verify-branches.mjs --file
```

Без `--file` проверяется `http://127.0.0.1:8000/`; тогда дополнительно нужен HTTP-сервер. Скрипт подключается к уже запущенному браузеру, а не запускает его самостоятельно. Снимки сохраняются в `.preview/`, которая исключена из учёта через `.gitignore`.

Проверяются загрузка используемых изображений, по пять секций проектов 01–04, утверждённые тексты и адрес CTA проекта 02, строго заданные изображения SVETLO и проекта 04, отсутствие ссылок в них, корректность SVG-разделителей и равных белых отступов вокруг полосы, непрерывность переходов АРК → Грантмастер → SVETLO → индустриальный музей и всех секций, отсутствие горизонтального переполнения и выхода текста за блоки, размещение текста Hero, геометрия навигации в обоих состояниях, отсутствие сдвига основного контента и переключение активных проектов 01–10. Проверяется непрерывность переходов 04 → 05 → 06 → 07 → 08 → 09 → 10. Также проверяются открытие всех изображений четырёх галерей, их порядок и подписи, циклическое листание, zoom, drag, сброс, закрытие и восстановление фокуса. Автоматические проверки дополняются визуальным просмотром; они не подтверждают все возможные размеры экранов и сценарии взаимодействия.

`tools/verify-hero.mjs --file` проверяет новый Hero на 1920, 1440 и 1280 px: загрузку исходных изображений, порядок 01–10, ссылки у всех 01–10, неподвижные градиенты, скрытый scrollbar, подъём на 5 px без масштаба и теней, колесо, перетаскивание, клавиатуру, плавные клики и перекрытие Hero проектом АРК. Снимки сохраняются в `.preview/`.

## Правила дальнейшей разработки

Каждый следующий проект сначала рассматривается как самостоятельная композиция, затем интегрируется в общий лендинг. При добавлении проекта необходимо:

1. Сохранить общий визуальный язык, не копируя механически композицию АРК.
2. Использовать только утверждённые материалы и уточнить реальные противоречия до реализации.
3. Сохранить модульность; использовать общие компоненты там, где это оправданно.
4. Подключить проект, его стили и необходимые галереи; добавить его в общий массив `projects`, чтобы зарегистрировать существующий контейнер в навигации 01–10 и автоматически поставить системный разделитель на границе с предыдущим проектом.
5. Обновить `src/site.js` после изменений JavaScript.
6. Проверить переход от предыдущего проекта к новому и весь лендинг минимум на ширинах 1920, 1440 и 1280 px, включая открытие через `file://`.
7. Убедиться в отсутствии новых наложений, разрывов, горизонтального скролла и непредусмотренного обрезания.
8. Сохранить уже утверждённые блоки, если задание не требует их изменения.

## Локальный Git

Перед крупными изменениями фиксируйте стабильное состояние проекта отдельным commit. После успешно проверенных изменений создавайте новый commit, чтобы всегда можно было безопасно вернуться к предыдущей рабочей версии. Исходники, изображения и необходимые материалы отслеживаются; временные результаты проверки и профиль браузера в `.preview/` исключены через `.gitignore`.

Этот `README.md` — единственный актуальный README проекта: он объединяет требования к дальнейшей разработке и сведения о фактической реализации. Исходные тексты и визуальные материалы сохраняют своё назначение.
